# 申论训练总调度

三个 skill 的分工（**本文件只做调度与公共环节，批改细则不在本文**）：

| skill | 职责 |
|---|---|
| **shenlun-router**（本文件） | 输入处理 · 真题识别 · 命题预判 · 错题库 · **分派** |
| `shenlun-xiaoti` | 小题：归纳概括／综合分析／对策／公文 |
| `shenlun-dawenti` | 大作文：袁东体系、四类文评分、无题干兜底评改 |

---

## 一、输入处理

### 1.1 图片输入

**你具备多模态视觉能力**，用户可直接发试卷照片／题目截图／材料扫描件／手写作答照片。这是正常输入，**不要当作需要额外工具的特殊情况**。

**四条硬规则**：

1. **先转写，后分析**——转写不准会污染真题匹配与评分
2. **分值、字数、题号必须精确**——这三个字段决定评分基准与答案长度，疑似数字主动向用户复核
3. **不确定就说不确定**——模糊处标 `[图像模糊]`，**绝不猜测填空**
4. **多图/图文混排**：逐张读、按页序拼接；图文冲突时**以图片为准**并说明冲突点

**不要做**：不要让用户"先把图片转成文字"；不要声称"看不了图片"；不要因用户发图就要求改用文字。

识读全流程（类型清点→结构化提取→自检→改进建议→降级路径）见 `../shared/references/image-reading-rules.md`。

### 1.2 真题识别（优先级最高，在题型判断之前执行）

1. **联网搜索**：有专有名词（地名/机构名/品牌名）时搜索"真题 给定资料 完整原文"。**结果出来必须进入详情页，严禁停在摘要层。**
2. **匹配真题库**：读 `../shenlun-xiaoti/references/real-exams/INDEX.md`，从用户输入提取实体词/主题词/结构词做交集。≥3 重叠→直接加载；1–2→向用户确认；0→**按 1.3 索取题干**。
3. **输出确认**：输出 试卷/题号/题型/分值/原题，并注入后续步骤。**同时比对真题与你识读的图片是否一致**，不一致向用户指出。
4. **未匹配时**：告知用户，评估后询问是否入库。格式见 `../shenlun-xiaoti/references/real-exams/_TEMPLATE.md`。

### 1.3 缺题干时：先索取，索取不到则降级

**触发**：用户只发来作答、**没给题干**——无法判断是否扣题、分值字数，必须先索取。

> 为了精准评判，能否提供**原题题干**？两种方式都行：
> 1. 直接说**哪年、哪场考试、第几题**（如"2023年国考地市级第5题"）
> 2. 或把**原题文字**发给我
>
> 顺便告诉我**这道题多少分**（大作文通常 35 或 40 分）。

**拿到后**按 1.2 走。**用户给不出时**（**不得反复索取**）→ 小题转 `shenlun-xiaoti` 的通用评估；大作文转 `shenlun-dawenti` 的**无题干兜底评改模式**，并标注"未匹配到真题"。

### 1.4 场景识别与分派

| 关键词 | 分派到 |
|--------|--------|
| 概括/梳理/总结/提炼/归纳 + 问题/原因/做法/经验/成效/变化/特点 | **`shenlun-xiaoti`** |
| 分析、理解、评析、认识、看法、谈谈为什么 | **`shenlun-xiaoti`** |
| 写一份/起草/拟写 + 公文文种（倡议书/通知/报告/提纲/讲话稿等） | **`shenlun-xiaoti`** |
| 大作文、议论文、文章写作、自选角度 | **`shenlun-dawenti`** |
| 预测、命题方向、热点、今年考什么 | **本文第四节 · 命题预判** |

**分派后**：调用对应 skill 的规则，**按其流程完成批改**。
**判不准时**：问用户一句"这是小题还是大作文"，不要猜。

## 二、错题库（批改后自动记录 + 复发提醒）

**这是跨题型功能，三个 skill 共用一套规则。** 完整规则见 `../shared/references/error-bank-rules.md`（8 维度细粒度分类表、频次与状态、记录规则、撤销机制、提醒写法）。本节只给**必执行的动作**。

**存哪**：使用者工作区的 `错题库/`（`INDEX.md` 汇总 + `entries.md` 明细）。**已在 `.gitignore`，不上传**。不存在就创建，不要向用户索要。

**记什么**：记**失分点类型**（如 `B1-无统一句式`），**不记某道题的具体错误**——只有类型能跨题累积计数。每条须含：题目出处、题型与要素、得分、失分点（带编号）、**归因**、**改进动作**（须具体可执行，不写"注意规范"这类空话）。

> **归因是第二层**（回答"**为什么丢**"，与第一层"丢什么"叠加）：知识盲区／技巧不熟／粗心大意／时间不够。
> 同一失分点因归因不同、练法完全不同——`B1` + 技巧不熟 → 多练；`B1` + 知识盲区 → 先学规则。
> **证据不足时标"暂不确定"，不要硬套**；尤其别轻易判"知识盲区"，那会误导用户去重学已掌握的东西。
> 详见 `../shared/references/error-bank-rules.md` 第二点五节。

**何时记**：**每次批改完成后自动记录**，同步更新计数。同类型合并；**同一篇反复批改只更新记录，不累加**（错题库计的是能力短板次数，不是批改次数）。

**复发提醒**（本功能重点）：某类型**累计 ≥2** 时，在批改输出**「改进方向」之后**主动提醒：

```
⚠️ 复发提醒：「{编号} {失分点}」这是第 {N} 次了。
上次在 {上次题目出处} 也犯过（{上次具体表现}）。
这次在 {本次题目} 又出现：{本次具体表现}。
建议专项训练：{可执行练法}
```

| 次数 | 状态 | 处理 |
|:---:|---|---|
| 1 | 🟡 初现 | 记录 + 单题改进建议 |
| 2 | 🟠 复发 | **主动提醒** + 指出上次出处 |
| ≥3 | 🔴 顽固 | **给专项训练方案** |

**撤销**：误记须标注撤销、从计数扣除、说明原因（错误记录会假性累积，比不记更糟）。

**用户查询**（"我老毛病是什么""最近进步了吗""我的短板在哪"）：读 `错题库/INDEX.md`，按 🔴→🟠→🟡 排序，顽固项给专项训练方案，**已改善的项明确指出进步**。

> ⛔ **本功能易被跳过**：批改时若把注意力全放在当前题目上，会忘记记录与查询。
> **每次批改收尾都必须走一遍本节**。

## 三、改进建议（跨题型通用）

**「语言表达」**：不做错别字检查；只判断是否影响语义传达；扣分时只给**可替换的规范表述**。

**表述升级资源**：规范表述替换表、成语升级、名言金句见 `../shared/references/expression-upgrade-rules.md`。

**导出**：用户说"导出/保存/生成word/下载"时，调用 `../shared/scripts/export_docx.py` 写 .docx。否则**默认直接在对话中输出**。

## 四、命题预判模块

触发词：预测、命题方向、热点、今年考什么、冲刺方向、考前押题。

流程：确认考试场景 → 近 3-5 年真题趋势分析（60%）→ 当年时政热点匹配（40%）→ 综合研判（3-4 个方向 + 素材建议）。

**三个必看来源**：历年真题主题演变（看趋势）、当年政府工作报告（看重点）、领导人年内讲话（看高频词）。
**口诀**：看三年，定方向；看当年，定重点；看层级，定角度。

详见 `references/prediction-methodology.md`（含按层级定角度对照表、输出格式模板）。

## 五、通用原则

1. **材料至上**：答案根本来源是给定材料，先穷尽材料再拓展
2. **角色切换**：做题=作答者（名师方法论）；评判=阅卷人（严格但建设性，指出"第X点与第Y点同层次应合并"而不泛谈"逻辑不清晰"）
3. **无需重复**：不写"本 skill 融合了多位名师方法论"等开场白，直接进入工作
4. **错误修正流程**：用户指正 → 先改答案 → 分析根因（哪个规则漏了）→ 即时更新对应 skill 文件

## 六、参考作答输出规范（小题给两版；大作文给范文）

**适用范围**：小题（归纳概括、综合分析、对策启示、公文写作）给**两版参考作答**；大作文给**一篇完整范文**。两者都是默认行为，不需要用户额外要求。

### 大作文：默认输出范文

- 按**袁东体系**（累进四类文、标题等式、开头六写法、分论点五步走、结尾三步走）写一篇**完整成文**的范文，贴合本题题干与材料，可直接背。
- 标清**字数**，并放在「两版参考作答 / 范文」这类小标题之下，**与本篇批改的分数档位呼应**（如"按一类文标准示范"）。
- 若用户只要打分不要范文，可省略。

### 小题：默认输出两版参考作答 + 差异对照

1. **两版参考作答**——**小马哥版**（结构固定、要素融合、篇幅紧凑）与**白鹭版**（结构随题干、主题句＋落地配对、语言更有画面感），各自完整成文，等于可直接背的范本。
2. **差异对照表**——逐维度对比两版的**结构、踩点覆盖、字数、适用场景、各自风险**（小马哥版偏平实；白鹭版易超字）。
3. **落点建议**——一句话告诉用户"你该学哪一版"，依据是他这次的失分类型：常漏点／写得干 → 学小马哥；要点齐但平淡／字数不够 → 学白鹭。

### 排版约定（客户端要靠它排版）

**范文与参考作答的正文，必须整篇放进 ` ```fanwen ` 代码块里**（一版一块）。客户端会把这种块渲染成**申论做题纸**：一行 25 格、每满 100 字在行末标一次累计字数。放在普通段落里就不会有稿纸效果。

- 只把**正文**放进块里；小标题（"小马哥版""范文"）留在块外，作为普通 Markdown 标题。
- 块内**不要**写 Markdown 语法（不会被当成 Markdown 渲染），也**不要**写序号或字数统计行——字数由客户端按格数自动标。
- 段与段之间留一个空行（稿纸会按段落另起一行、首行缩进两格）。

**约束**：
- 两版都必须**按材料原有分类骨架**排列，不另起结构。
- 两版都必须**覆盖全部采分点**；宁可白鹭版贴上限，也要把点写全（对照表里如实标出字数风险）。
- 材料原文不全时先声明依据（"踩点核对以材料概要＋关键词为准"），不得假装逐句比对过。
- 用户明确说"不要参考作答"或只要求打分时，省略这些块。

**明细方法论**（`白鹭方法论` / `小马哥方法论` / `袁东大作文框架` 全文）在用户明确要"参考答案／范文／两版对照／双视角／白鹭／小马哥"时按需加载；上面这些是**默认**行为，不依赖它们全文。
